# Annotation data — provenance warning

Read this before using anything in this directory.

## The short version

`dataset_train.csv` contains **800 manually annotated rows. 116 of them (14.5%)
are not present in the raw scrape** `data/raw/tiktok_comments_mobil_dinas_kaltim.csv`,
and they exist in no other CSV in `backup/`. That scrape batch is gone.

Those 116 rows **do train the models** (via
`data/processed/dataset_train_clean.csv`) but **cannot receive a corpus
prediction**, because no row of the analysable corpus corresponds to them. That is
why the corpus accounting is `684 located + 116 unlocatable = 800` annotated rows
but the prediction file covers only the 1031 corpus rows.

## The missing rows are not a random sample

This is the part that changes how the results must be read. The 116 unlocatable
rows are overwhelmingly `Responsivitas` and `Transparansi`:

| Aspect | % of the 684 located rows | % of the 116 unlocated rows |
|---|---:|---:|
| Akuntabilitas | 50.6% | 14.7% |
| Efektivitas & Efisiensi | 37.1% | 7.8% |
| **Responsivitas** | **7.0%** | **44.0%** |
| **Transparansi** | **5.3%** | **33.6%** |

The sentiment split is *not* skewed the same way (90.1% negative among located
rows vs 87.1% among unlocated rows), so this is a **topic** sampling problem, not
a difference in labelling tone.

Consequence for the reported results: the annotation sample over-weights
`Responsivitas + Transparansi` to **21.75% of the training set against 9.31% of
the corpus — 2.34×**. The aspect classifier's prior is therefore tilted towards
the two aspects the corpus barely contains.

Full numbers, including a chi-square test of independence
(χ² = 248.73, df = 3, p ≈ 1.2 × 10⁻⁵³, Cramér's V = 0.558, threshold 0.10)
and the same test on sentiment (χ² = 0.95, df = 1, p ≈ 0.33, Cramér's V = 0.035):

- `data/results/provenance_audit.csv`
- `docs/BUG_TRACKER.md` → BUG-07

Regenerate everything with:

```
python -m analysis.provenance_audit
```

## Files

| File | What it is |
|---|---|
| `dataset_train.csv` | 800 annotated rows. The training set. |
| `annotated_not_in_corpus.csv` | The 116 annotated rows with **no counterpart in the raw scrape**, with their full annotations. Generated by the audit script; preserved here so these rows can never be silently lost again. |
| `aspect_sentiment_annotation_*.csv`, `aspect_annotation_template.csv` | Earlier annotation working files. `aspect_sentiment_annotation_final.csv` is the annotated file that accounts for 88 of the 116 unlocatable rows. The others are templates with blank label columns. |

`annotated_not_in_corpus.csv` is a byte-identical copy of
`data/results/provenance_missing_rows.csv`; it lives here as well because it is
annotation data, not a result.

## Required disclosure

This must be stated as a limitation in **Chapter 3** (methodology) and repeated
in the caveats of **Chapter 5**: the corpus and the annotation sample were drawn
from **two different scrape batches**, and the annotation batch over-represents
`Responsivitas` and `Transparansi` relative to the corpus by a factor of 2.34.
Aspect-level figures for those two aspects — including the 64 and 32 row counts
and the zero positive predictions — inherit that bias and cannot be read as
measures of public opinion on those aspects.

See `docs/BUG_TRACKER.md` BUG-07 for the full audit and `docs/RESULTS_FIXED.md`
section 6 for the caveat wording to reuse.
